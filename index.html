Why Aster

The research project is the unit of work.

A coding environment treats the repository as the unit of work. Aster treats the research project as the unit: the conversations that start the work, the Experiments and Runs that produce results, the paper that reports them, the papers it cites, the GPUs it runs on, and the deadline it is aiming for. Claude Code and Codex do the work in your terminal as usual; Aster records what they actually ran and puts the evidence next to every number they report.

  • Conversation first

    Start from a Claude Code or Codex chat. An Experiment groups the results afterwards; it is not a form to fill in before you can talk to an agent.

  • Runs with provenance

    Every launch records its command, commit, uncommitted diff, host, agent session, log, and metrics. An agent ending its turn never marks a Run as succeeded.

  • Numbers backed by Runs

    Each result number in the manuscript can point to a Run, metric, and split. Aster flags numbers that changed, went stale, or have nothing behind them.

  • You approve, agents execute

    Agents propose the next Run with a reason and the exact command. Only you approve it, and the approved command is what runs.

  • Agents stop polling

    Watches wake an agent when a Run ends, fails, logs NaN, stalls, or crosses a threshold — on your machine or over SSH and SLURM.

  • Your machines, your files

    No Aster account or hosted service. Agents and research records stay on your computer and the hosts you connect, in plain files inside the project.

How it works

Agents do the work. Aster keeps the record.

Your agent launches every experiment through a small research harness. The harness writes what it observed into .aster/ in your project, and Aster reads those records live.

  1. Ask

    Describe the experiment in a Workbench chat or the Experiment agent pane. Aster attaches the project context — Runs, metrics, open findings — as a compact chip, not a wall of text.

  2. Run through the harness

    The agent launches training with run exec --experiment <slug> -- python train.py …. The harness runs only that command and records the launch commit, a patch of uncommitted changes, host, argv, and agent session.

  3. Record, don’t claim

    Metric lines your code prints (ASTER_METRIC {…}) stream into metrics.jsonl; stdout and stderr go to train.log; the exit code decides the Run’s state.

  4. Watch

    aster research watch registers what the agent is waiting for. Aster checks local Runs every 15 s and SSH Runs every 60 s and wakes the agent when one fires, so nobody polls.

  5. Decide

    The agent records findings with evidence — a metric, log lines, a file — and proposes the next Run. The proposal appears under Needs you in the notebook; you approve or reject it.

  6. Write

    When a number goes into paper/main.tex, the agent records a claim that ties it to a Run’s metric. Writing shows each claim as verified, stale, mismatched, or missing evidence.

Plain files in your project

Everything lives in the project as JSON, JSONL, and logs you can read, diff, and commit.

Project layout
my-project/
  paper/main.tex  paper/references.bib
  .aster/
    project.json          path map of the project
    claims.json           manuscript numbers → Run evidence
    experiments/<slug>/
      experiment.json     question, hypothesis, metric, baseline, seeds
      loop.jsonl          hypothesis → Run → result → decision
      proposals.jsonl     next-Run proposals and your decisions
      quality.jsonl       findings with evidence
      analysis.jsonl      analyses and the Runs they used
      runs/<id>/
        run.json  metrics.jsonl  train.log  code.patch
        config.json  media.jsonl  artifacts/
    library/papers/

Features

From the first chat to the number in the paper.

Experiments, Runs, the manuscript, the papers it cites, and the GPUs it runs on, side by side in one window.

01

Experiment notebook

Each Experiment opens on a notebook: the plan (question, metric, baseline, seeds), Needs you (failed Runs, proposals, and findings waiting on a decision), results with mean ± spread per configuration, analyses, and your conclusion.

The Experiment agent is docked beside it and can design, analyze, explain a failure, or propose the next Run.

02

Runs

Live metric curves, the log, config, code patch, and media for every Run.

Attach existing JSONL or CSV results, link a SLURM job, or let agents register Runs that Aster picks up on its own.

03

Compare

Line up 2–6 Runs: baseline, last and best values at one precision per column, mismatched units or evaluation conditions, config differences, and model outputs — text or image — matched by sample ID.

Rate samples blind, A/B, and see how your ratings agree with the agent judge.

04

Writing and Claims

TeX source, the PDF compiled with Tectonic, and a writing agent side by side, with SyncTeX in both directions.

The Claims drawer marks every recorded number as verified, stale, mismatched, or missing evidence, lists result-like numbers no Run backs, and fixes a stale number in one click.

05

Research loop

Give an agent an objective, a metric, and a budget of Runs and hours. It writes each hypothesis, Run, result, and decision to the loop ledger and launches only through the harness.

It stops for you before going over budget or changing the evaluation.

06

Library

The project’s papers and PDFs with highlights and notes, arXiv and DOI import, and copyable citations.

A reading agent summarizes a paper or relates it to your manuscript and code. Drag the divider to give the PDF or the agent more room.

07

Compute and Deadlines

SSH hosts, GPUs, and SLURM queues across projects, with a GPU budget per host and project: jobs over budget are submitted held and released in priority order.

Conference deadlines from the ccfddl and Hugging Face AI deadlines catalogs, in your time zone.

08

Workbench and Code layout

Chats, terminals, the editor, files, and Git for the project. Switching pages never stops an agent or terminal.

The Research | Code switch flips the sidebar to a worktree-first layout for pure coding work.

Research harness

One small CLI for every experiment.

The harness is a zero-dependency Node CLI that agents call for every experiment. The app ships the same code and imports it at runtime, so the agent and the UI always agree on what a record means.

  • run exec runs only the command it is given. Nothing in the harness starts training or decides that a result succeeded; the exit code does.
  • A claim’s value is read from metrics.jsonl. A --value that disagrees with the Run is refused.
  • An agent finding needs evidence, and the harness checks each item against the Run’s files.
  • Only you approve, reject, accept, or dismiss.
Terminal
HARNESS=$(aster research harness-path)

# Launch a Run: only this command runs, and its metrics are recorded
node $HARNESS run exec --experiment lora-r16 --id seed-42 \
  --metric-def loss:minimize --metric-def acc:maximize:% \
  -- python train.py --lr 3e-4

# Tie a manuscript number to that Run's metric
node $HARNESS claim add --text "LoRA reaches 83.0% validation accuracy" \
  --run lora-r16/seed-42 --metric acc --split val --format percent:1

# verified / stale / mismatch / missing-evidence
node $HARNESS claim audit

Install

  1. Open the .dmg and drag Aster into Applications.

  2. First launch. Builds are signed ad hoc and not notarized yet, so macOS blocks the first open. Right-click Aster → Open → Open, or run:

    xattr -dr com.apple.quarantine /Applications/Aster.app

  3. Sign in to at least one agent CLI: Claude Code or Codex. Any other CLI agent runs in a terminal tab.

  4. Open a project: Home → Add project and pick a folder. For a new project, create an Experiment or a manuscript and Aster writes .aster/ and paper/ for you, without overwriting existing files.

Requirements

  • RequiredA Mac with Apple Silicon, macOS 12 or later.
  • RequiredAt least one agent CLI signed in: Claude Code or Codex.
  • OptionalTectonic on PATH to compile PDFs.
  • OptionalSSH access to your GPU hosts, with SLURM to submit jobs.

Aster keeps its own data in ~/Library/Application Support/Aster and research records inside each project.

FAQ

Questions

Is it free?
Yes. Aster is open source under the MIT License.
Which agents does it work with?
Claude Code and Codex in chat. Any other CLI agent runs in a terminal tab.
Does my data leave my machine?
There is no Aster account or hosted service. Agents and research records stay on your computer and the hosts you connect. Agents talk to their own model providers, as they do outside Aster.
Can I use it on my phone?
On your phone, use the Paseo app for agent chat; Aster is desktop-only.
Windows or Linux?
Not published yet. Current builds are for macOS on Apple Silicon.
